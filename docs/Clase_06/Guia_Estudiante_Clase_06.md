# PROGRAMACIÓN APLICADA 2026-2
## CLASE 06
**Primera implementación física en PostgreSQL: DataGrip, DDL y constraints**

**GUÍA DEL ESTUDIANTE**
Observa ParkFlow 360 y transfiere el método a tu proyecto.

### 1. Qué cambia en esta clase
Hoy el trabajo de diseño (Clase 02 a 05) comienza a existir de verdad dentro de PostgreSQL.
Hasta hoy: diseño. Desde hoy: diseño + ejecución + verificación + evidencia reproducible.

### 2. Qué debes aprender hoy
* Entender la diferencia entre PostgreSQL y DataGrip.
* Conectarte a PostgreSQL desde DataGrip.
* Crear una base de datos específica para tu proyecto.
* Traducir 4-6 tablas núcleo a CREATE TABLE.
* Implementar PK, FK, NOT NULL, UNIQUE y CHECK.
* Respetar el orden de creación.
* Probar violaciones de integridad.
* Guardar el DDL como migración versionada en Git.

### 3. Qué debes observar mientras el profesor trabaja ParkFlow 360
| Lo que hará el profesor | Lo que debes aprender, NO copiar |
|---|---|
| Creará la base parkflow360 | Cómo nombrar y crear una base. |
| Creará parking_lot antes de zone | Cómo ordenar tablas. |
| Usará UNIQUE compuesto | Cómo expresar unicidad contextual. |
| Usará CHECK para estados | Cómo impedir valores inválidos. |
| Provocará errores | Cómo verificar que PostgreSQL protege los datos. |

### 4. Lo que NO debes copiar de ParkFlow
No copies nombres, entidades, estados, cardinalidades ni tipos de datos que no apliquen a tu proyecto.

### 5. Archivos que debes tener abiertos
Ficha oficial, modelos conceptual y relacional, DER lógico, modelo físico y plan de migración. Repositorio Git actualizado.

### 6. Paso 1 - Identifica tus primeras 4-6 tablas núcleo
Selecciona el núcleo mínimo que permita demostrar relaciones y restricciones.
(Ej. entidad raíz -> entidad dependiente -> otra entidad/catálogo).

### 7. Paso 2: Crea la base de datos de TU proyecto
```sql
CREATE DATABASE nombre_de_tu_proyecto
WITH OWNER postgres ENCODING = 'UTF8';
```

### 8. Paso 3: Crea la carpeta de migraciones
`backend/src/main/resources/db/migration/`

### 9. Paso 4: Escribe primero el DDL en archivo
Archivo: `V1_init_core.sql`.

### 10. Plantilla genérica de CREATE TABLE
Adapta esta plantilla a tu modelo:
```sql
CREATE TABLE nombre_tabla (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    campo_obligatorio VARCHAR(100) NOT NULL,
    campo_opcional VARCHAR(150),
    activo BOOLEAN NOT NULL DEFAULT TRUE,
    created_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
    CONSTRAINT uq_nombre_tabla_campo UNIQUE (campo_obligatorio),
    CONSTRAINT ck_nombre_tabla_campo CHECK (BTRIM(campo_obligatorio) <> '')
);
```

### 11. Plantilla genérica para tabla hija con FK
```sql
CREATE TABLE tabla_hija (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    tabla_padre_id BIGINT NOT NULL,
    codigo VARCHAR(30) NOT NULL,
    created_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
    CONSTRAINT fk_tabla_hija_padre FOREIGN KEY (tabla_padre_id) REFERENCES tabla_padre(id),
    CONSTRAINT uq_tabla_hija_padre_codigo UNIQUE (tabla_padre_id, codigo)
);
```

### 12. Paso 5: Verifica cada decisión antes de ejecutar
Revisa PK, FK, NOT NULL, UNIQUE, CHECK, DEFAULT.

### 13. Paso 6 - Ejecuta en orden de dependencias
Tablas sin FK primero, luego las hijas.

### 14. Paso 7: Inserta un dataset mínimo válido
```sql
INSERT INTO nombre_tabla (campo_obligatorio) VALUES ('dato de prueba');
```

### 15. Paso 8: Obligate a comprobar restricciones
Prueba fallos de NOT NULL, UNIQUE, FK, CHECK. No los corrijas, entiéndelos.

### 16. Paso 9: Inspecciona la estructura mediante SQL
Consulta `information_schema`.

### 17. Paso 10: Registra evidencia en tu documentación
Documenta la base creada, tablas de V1, orden, PK/FK/UQ/CK y errores provocados.

### 18. Paso 11: Versiona con Git
```bash
git add backend/src/main/resources/db/migration/V1_init_core.sql
git commit -m "feat(db): create initial core schema"
```

### 19. Revisión cruzada obligatoria
Revisores comprueban DER, FKs, restricciones, dependencias y convenciones.
